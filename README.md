# mdmis-backend

FastAPI backend for MDMIS (Mineral Detection & Mining Intelligence System),
targeting Neon (serverless Postgres). Async throughout: SQLAlchemy 2.0 async
ORM, asyncpg driver, Alembic migrations.

## Apps

- `accounts` — Organisation + custom User model (10 SRS roles), JWT auth (register/login/refresh/me)
- `sites` — mining sites/concessions
- `scans` — ScanSession, MineralZone
- `traceability` — MineralBatch (auto-generated chain-of-custody id), CustodyEvent (immutable)
- `safety` — SafetyIncident (+ acknowledge action)
- `transport` — Shipment
- `compliance` — ComplianceReport

All client-data models carry an `organisation_id` and every query is scoped
to it via `app.crud.org_scoped_crud_router` — one org can never read or
write another org's records (`system_admin` is the only exception).

## Setup

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
copy .env.example .env        # fill in DATABASE_URL (Neon connection string)
python -m alembic upgrade head
python -m app.seed            # creates demo org, 4 demo users, 10 sites
python -m uvicorn app.main:app --reload
```

Without a `DATABASE_URL` set, it falls back to a local SQLite file
(`db.sqlite3`) so the project runs out of the box. A plain `postgresql://`
Neon connection string works as-is — it's rewritten to
`postgresql+asyncpg://` automatically, and `sslmode=require` is translated
into the asyncpg SSL connect arg.

## Migrations

```bash
python -m alembic revision --autogenerate -m "describe the change"
python -m alembic upgrade head
```

Note: autogenerated migrations reference the custom `GUID` type
(`app.types.GUID`) used for every UUID primary/foreign key — the import is
already wired into `alembic/script.py.mako`, so new migrations pick it up
automatically.

## Preparing external datasets

Datasets downloaded from Kaggle, open-data portals or survey exports usually
carry extra columns, other units and bad rows. `tools/prepare_dataset.py`
filters them down to exactly what MDMIS ingests — deterministically, with a
reason for every dropped row:

```bash
pip install -r requirements-dev.txt          # pandas + openpyxl (dev only)
python tools/prepare_dataset.py --list-targets
python tools/prepare_dataset.py survey.csv --target magnetometer
python tools/prepare_dataset.py assays.xlsx --target lab --region none
python tools/prepare_dataset.py data.csv --target gamma --map th_ppm=eTh_value
```

Targets: `magnetometer`, `gamma`, `em`, `lab` (element ppm, converts ppb/%
and oxide grades such as SnO2 / Ta2O5 / WO3 / Li2O), `occurrences` (keeps only
minerals MDMIS tracks), `gas` and `geotechnical` (also writes ready-to-POST
`/api/ingest/readings` JSON). Points outside Rwanda are dropped unless
`--region none` or a custom `min_lat,min_lon,max_lat,max_lon` is given.

Each run writes `<name>.mdmis-<target>.csv` (upload it on Sensor Data →
Path 1), `<name>.rejected.csv` (every dropped row + reason) and
`<name>.report.json` (column mapping, conversions, counts per rule).
